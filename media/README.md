# bobine-media (experimental)

A read-only audio inspector. It is experimental and off by default in the application (setting `media_native`, see below). It does not open a network port, spawn a shell, decode audio, modify media or access a database. The existing ffprobe/ffmpeg path remains necessary for unsupported inputs and images.

Build and check with `cargo test --locked`, `cargo clippy --all-targets -- -D warnings`, and `cargo build --release --locked`. Run `target/release/bobine-media`; send one JSON-RPC object per UTF-8 line on stdin. Responses are JSON only on stdout; EOF exits. A final line without a newline is accepted. Diagnostics never include input paths. Detailed protocol: [PROTOCOL.md](PROTOCOL.md).

## Experimental subset

Every reader is a strict whitelist that reproduces what ffprobe reports for the layouts it understands and refuses the rest (`unsupported`, `ambiguous_metadata`, `ambiguous_cover`) so that the caller runs the reference path. Tag values are read without replacement characters; duplicated, unknown or multi-valued items are refused rather than merged.

- MP3 (Layer III, MPEG-1/2/2.5): optional ID3v2.3/2.4 tag with unique, unflagged text frames (title, artist, album, album artist, track, disc, date, genre, encoder) and any number of `APIC` frames (several pictures only make the cover ambiguous). Duration, by the rule ffmpeg applies: a Xing/Info frame with a frame counter (`frames x samples-per-frame / rate`, minus the 12-bit delay and padding when the encoder is LAME, Lavf or Lavc; Lofty's raw count must agree within 0.4 s); a VBRI frame (version 1, `frames x samples-per-frame / rate`); **without any index, `bytes / bitrate`, only when every frame of the file announces the same bitrate and the last frame ends exactly at the end of the file**. A CRC-protected index frame is refused (ffmpeg does not find the index there), as is a variable-bitrate stream without index (ffmpeg estimates from the packets it probed, not reproduced), free format, ID3v1/APE, custom frames, numeric genre mappings and ambiguous dates.
- FLAC: mandatory STREAMINFO, optional padding/seek table, one bounded Vorbis comment block with known fields, and picture blocks.
- WAV: little-endian RIFF PCM, one `fmt `/`data`, optional padding and **one `LIST`/`INFO` chunk limited to the identifiers ffmpeg renames** (`INAM`, `IART`, `IPRD`, `ICRD`, `IGNR`, `IPRT`, plus unread `ISFT`, `ICMT`, `ICOP`, `ILNG`, `ITCH`, `ISMP`). Any other identifier keeps its raw four-letter name in ffprobe (it could collide with a field name): refused.
- M4A: MPEG-4 audio, `ftyp` brand `M4A `/`isom`/`mp42`, one progressive AAC or ALAC track, iTunes `ilst` items (title, artist, album, album artist, date, genre, `trkn`, `disk`, `covr`; a few unread items skipped). Duration: the movie header, accepted only if the edit list (or the media header) agrees within 1 ms. A movie or media creation time becomes the year when no date tag exists, as in ffmpeg. Fragmented files, several tracks, QuickTime keys and free-form items are refused.
- Ogg Vorbis and Ogg Opus (`.ogg`, `.opus`): one logical stream with the standard header packets and a comment header with known fields (a `METADATA_BLOCK_PICTURE` comment is a cover). Duration: granule position of the last page over the sample rate (48 kHz for Opus, pre-skip not subtracted, like ffprobe). It holds only if the stream starts at sample zero, so the first audio page must announce exactly the samples of its own packets (Vorbis block sizes are read from the setup header's mode table, Opus from the table of contents), and the last page must carry the end-of-stream flag. A short file whose audio is a single page, a chained or multiplexed file, or a stream that does not start at zero is refused.
- AIFF (`.aiff`, `.aif`): `FORM`/`AIFF` PCM with `COMM`, `SSND`, and `NAME` (title), `AUTH` (author), `(c) `, `ANNO`; the sound data length must match the frame count. AIFF-C and `ID3 ` chunks are refused.
- Not read natively: raw ADTS AAC (ffmpeg estimates its duration from a bitrate it measures), WMA/ASF (Lofty has no ASF reader, and the importer transcodes it with ffmpeg anyway), `.mp4`/`.m4b`/`.oga`, and every other format.
- `extract_cover` gives the raw embedded picture for the structurally accepted JPEG/PNG families, proves an absence, and otherwise answers `ambiguous_cover` (see PROTOCOL.md).

### Equivalence of covers

For a picture, the reference ffmpeg-then-Pillow pipeline and the native raw-bytes-then-Pillow pipeline cannot give the same bytes: ffmpeg decodes the picture and re-encodes a lossy JPEG (4:2:0, a low quality) before Pillow converts, shrinks to 600x600 and saves a quality-85 JPEG, and that first re-encode is the one thing the native path skips (measured: the intermediate JPEG is never equal to the embedded bytes, even for a JPEG source). The two final files are therefore **defined equivalent** when, decoded to RGB, they have the same dimensions, a PSNR of at least 33 dB and a mean absolute error of at most 4 (0-255). Measured here: real artwork 38-48 dB (mean error 0.4-1.6), a deliberately harsh fractal image with sharp edges 34.3-36 dB (mean error up to 3.5); on the 656-file corpus every one of the 127 pictures that go native passes (minimum 34.31 dB, maximum mean error 3.5). The definition is implemented in `scripts/media-bench/cover_equivalence.py` and enforced by the comparison bench and the import bench. Structural limits keep outside the native path what is known to differ: a rotated EXIF orientation (ffmpeg rotates, Pillow's `open` does not), CMYK, Adobe-marked, arithmetic or 12-bit JPEG, 16-bit, interlaced or animated PNG, a declared MIME type that contradicts the bytes, several pictures. Covers already imported are never regenerated.

The whitelist describes parser eligibility, not production certification of every file with these extensions. Compare every accepted file with the reference oracle before enabling any profile. `radio-v1` and `course-duration-v1` remain distinct profiles; their current equal result for these simple single-audio layouts must not be generalized to other containers. Filename-derived titles and ordering remain the caller's responsibility.

## Resource and lifecycle limits

Initial limits are experimental: request 64 KiB, response 8 MiB (both excluding LF/CRLF), cover 4 MiB, media file 512 MiB, aggregate metadata 4 MiB, text block 64 KiB, metadata/chunk count 128, Vorbis items 256 and cumulative physical reads 16 MiB per request (an MP3 without index of at most 128 MiB may be read once in full to check its bitrate). Oversized request frames are discarded without allocating a full line, followed by a structured error. The parser does not decode images; it checks their structure and a 40-million-pixel ceiling.

Lofty is pinned to 0.22.4. Its per-thread `GlobalOptions::allocation_limit` is set to 4 MiB before each parse, custom resolvers and format-specific preservation are disabled, strict parsing is selected, and tag/image allocation is avoided with `read_tags(false)`/`read_cover_art(false)` after bounded preflight inspection. This is not a hard process RSS cap. 

The crate uses the repository's AGPL-3.0-or-later license. Lofty, Serde and serde_json are MIT OR Apache-2.0; locked transitive dependencies also provide permissive license choices (including Unicode-3.0 and zlib notices). Preserve their license notices when distributing binaries. Cargo.lock fixes the exact dependency graph.

Only absolute Unicode paths to regular local files are accepted; symbolic links and special files are rejected. Path normalization and replacement characters are never applied. POSIX non-UTF-8 paths cannot be represented by this protocol and must use the reference path. This executable is an internal subprocess, not a filesystem security boundary: the caller must supply trusted local paths and prevent hostile concurrent replacement. Metadata is checked before/after inspection to detect ordinary source changes.

The caller owns startup, serialization, deadlines, cancellation and process collection. Suggested development deadlines are 2 seconds for `hello` and 5 seconds for an inspection; these are caller policies, not timers implemented inside the parser. EOF stops the process between requests. A parent dying during a blocked filesystem operation is not guaranteed to terminate an active request; the supervisor must handle that case before distribution.

No hardware profile is certified by the native unit tests. Android/Bionic packaging and lifecycle, Windows process flags and Unicode, macOS signing, and Linux/appliance packages require separate validation.

## Building, staging and measuring

- CI (`media-component` job): fmt, clippy `-D warnings`, `cargo test --locked` and a release build on Linux amd64/arm64, Windows x64 and macOS, plus (Windows ARM64, optional) and a license gate, `scripts/ci/check-media-licenses.py`, which rejects any shipped dependency without a permissive license. This proves that the crate builds and passes its tests there; it does not prove packaging or any device.
- Staging: `python3 scripts/ci/stage-media.py --dest <dir>` builds with `--locked`, copies the executable, starts it, requires a protocol-1 `hello` answer and a clean exit on EOF, and prints size and SHA-256 (`--check <path>` only checks an installed executable). The Linux `.deb` jobs (amd64 and arm64), the Windows jobs and the macOS job call it, so those packages contain `bobine-media` next to `BobineBackend` (macOS: `Contents/MacOS`); a package built without it stays complete. The headless appliance (`install.sh`, run from a git checkout) does not ship it.
- Where the application looks for the executable (`backend/app/utils/media_sidecar.py`): the `BOBINE_MEDIA_SIDECAR` or `BOBINE_MEDIA_BIN` override (one literal path), else next to the frozen executable (Linux `/usr/lib/bobine`, Windows install directory, macOS `Contents/MacOS`) or in `Contents/Resources`, else `media/target/release` in a source checkout. Android discovers `libbobine_media.so` in `nativeLibraryDir` and sets `BOBINE_MEDIA_BIN`; `scripts/ci/build-media-android.sh` builds it (NDK r28+, 16 KiB alignment checked on the ELF) for arm64-v8a and armeabi-v7a; the Android CI job and the Play workflow run it and `verify-apk-abis.sh` requires `libbobine_media.so` in every ARM ABI.
- Activation: the `media_native` setting (Réglages → Composant audio natif, off by default, the only way on Android), `GET /api/settings/media-native` reporting `disabled`/`active`/`fallback`/`absent`; the environment variable `BOBINE_MEDIA_NATIVE` (`1` forces on, `0` forces off) takes priority. A component that is missing, fails or declines a file never loses a media: the reference path runs.
- Measure: `scripts/media-bench/` generates the synthetic corpus (`--scale 540` gives 600+ tracks), compares the component with the reference path (`compare.py`, per-file field and duration differences) and times a full import in both modes (`import_bench.py`: wall, CPU, peak memory, processes, disk, imported rows compared). Results are valid for the machine that ran them only.
