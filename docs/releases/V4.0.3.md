# CE QUI CHANGE DANS LA VERSION 4.0.3

### 1. Support de Firefox
- **Vérifié sur Firefox 157** : l'interface d'administration et les lecteurs ouverts depuis un poste tiers (`/radio`, `/kiosk`, `/cinema`, `/coach`) — WebSocket, envoi de fichiers, lecture par plages (`Range`), Web Audio et lecture H.264 (jusqu'à 1080p60 à 60 Mbit/s, sans image perdue) fonctionnent ; manettes et Wake Lock : API présentes (contexte sécurisé requis hors `localhost`).
- **Limites connues, documentées** : `HEAD` sur les flux média renvoie du HTML, le glisser-déposer filtre par type MIME, et le décodage HEVC/AV1 dépend du système et du matériel du navigateur.
- **Plan d'implémentation publié** (9 lots F0 à F8 : conformité HTTP des flux, import reprenable par morceaux, profil vidéo lisible partout, lecteurs tiers, diagnostic intégré, outillage CSS/JS) : [`docs/PLAN-COMPATIBILITE-FIREFOX.md`](../PLAN-COMPATIBILITE-FIREFOX.md) — version anglaise [`PLAN-COMPATIBILITY-FIREFOX.en.md`](../PLAN-COMPATIBILITY-FIREFOX.en.md).
- **Banc de mesure reproductible** : [`scripts/browser-bench/`](../../scripts/browser-bench/README.md).
- Le ralentissement d'import signalé sous Firefox **n'a pas été reproduit** (31 fichiers, 1,5 Go, lien limité à 32 Mbit/s, 2 cœurs) : sa cause reste à établir avec le protocole du plan.
- Firefox est une marque de la Mozilla Foundation ; son logo est utilisé uniquement pour indiquer la compatibilité, sans affiliation.

### 2. Mises à jour et canaux Stable / Bêta fiabilisés (toutes plateformes)
- **Android** : correction de l'échec « `PyApplication` has no attribute `context` » qui bloquait toute mise à jour depuis l'application.
- **APK Android TV** : le bon APK (téléphone ou TV) est choisi par variante ; l'application ne télécharge plus rien d'elle-même au lancement ; l'APK est vérifié (SHA-256, paquet, signature, `versionCode`) avec des messages explicites.
- **Retour en Stable depuis la Bêta** : le sélecteur de canal propose désormais la dernière Stable, signalée comme retour en arrière ; la planification automatique n'applique jamais un retour en arrière.
- **Mise à jour réussie affichée en échec** : l'issue est déduite en comparant l'empreinte version/commit avant et après le redémarrage.
- **Écrans rechargés pour rien** : plus de rechargement forcé au début d'une mise à jour ; les clients se rechargent seuls au redémarrage réel du serveur.
- **Vérification GitHub robuste** : cache avec ETag, erreurs distinguées (hors ligne, limite de requêtes, Bêta en cours de republication), téléchargement en `.part` avec trois tentatives, retour arrière automatique de l'appliance headless si la compilation échoue.

### 3. Installation sans friction
- **`curl … | bash`** fonctionne désormais depuis un tube : le script récupère le code, demande sudo seul, installe `git` et `curl` au besoin, affiche une progression soignée, l'URL du réseau local et un QR code en fin d'installation.
- **Assistant Tauri** : scan réseau qui suit le vrai masque (de /24 à /22), sockets plafonnées, table ARP et `bobine.local`, champ « Scanner un autre réseau », résultats en direct ; connexion par nom d'hôte ; `install.sh` embarqué et envoyé sur la borne ; échec affiché avec « Réessayer » et « Copier le journal ».
