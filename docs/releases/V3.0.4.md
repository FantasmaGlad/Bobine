# Bobine V3.0.4 — Performance et Stabilité Réseau Android, Thème Charbon Sombre

<p align="center">
  <img alt="Bobine" src="https://raw.githubusercontent.com/FantasmaGlad/Bobine/main/Assets/Images/bobine_banner.svg" width="100%">
</p>

La version 3.0.4 corrige une cause racine de lenteur réseau et d'instabilité sur la version Android : la base de données et les fichiers à forte fréquence d'accès résidaient sur un stockage externe lent, bloquant occasionnellement le serveur pour tous les clients connectés. Cette version déplace ces fichiers vers le stockage interne rapide de l'appareil, sort les accès disque bloquants de la boucle d'évènements, fiabilise la diffusion en temps réel vers les écrans et tableaux de bord, et ajoute un nouveau thème sombre. L'installateur headless configure désormais correctement les sorties audio dès le premier déploiement.

---

## 1. Cause racine et correctifs de performance (Android)

Diagnostic complet dans [`docs/audit-android-2026-09-11.md`](https://github.com/FantasmaGlad/Bobine/blob/main/docs/audit-android-2026-09-11.md).

- **Stockage réparti sur deux racines** : la base de données SQLite, les miniatures, les journaux techniques et les pochettes radio résidaient sur le stockage externe de l'application (servi par FUSE, significativement plus lent que le stockage interne) — chaque requête à la base pouvait bloquer la boucle d'évènements du serveur pour tous les clients connectés en même temps. Ces fichiers sont désormais placés sur le stockage interne rapide de l'appareil ; les médias volumineux (vidéos, fonds animés, pistes audio) restent sur le stockage externe, adapté à la lecture séquentielle de gros fichiers. Une installation existante est migrée automatiquement, sans risque : copie vérifiée par contrôle d'intégrité, jamais de suppression de l'original.
- **Accès disque sortis de la boucle d'évènements** : les lectures de la base de données déclenchées par le streaming vidéo et par les commandes de lecture s'exécutent désormais dans un bassin de threads dédié plutôt que directement sur la boucle asynchrone principale du serveur.
- **Diffusion WebSocket parallélisée** : l'envoi d'un évènement à tous les écrans connectés se fait maintenant en parallèle avec un délai de garde par client, au lieu d'un envoi séquentiel où un seul appareil lent retardait tous les autres.
- **Keepalive assoupli** : le délai de tolérance avant de considérer une connexion morte est porté de 20 à 60 secondes, adapté aux limitations de minuteurs que les navigateurs appliquent aux pages en arrière-plan ; un signal de vie est également envoyé dès qu'une page redevient visible.
- **Cache des vues Web natives revalidé** plutôt que désactivé, réduisant le volume de données retéléchargées à chaque affichage d'écran.

## 1bis. Tableau de bord réseau — gel silencieux corrigé

Trouvé et corrigé après le déploiement initial de cette version : le tableau de bord d'administration pouvait geler silencieusement lorsqu'il pilotait un écran sur le canal réseau depuis une connexion Wi-Fi réelle — la position affichée s'arrêtait d'avancer sans qu'aucune erreur ne soit visible, jusqu'à ce que la connexion finisse par se rétablir d'elle-même, donnant une impression de répétition (la position semblant reculer puis rattraper son retard). Cause : un envoi vers un client jugé trop lent était silencieusement abandonné côté serveur sans jamais en informer ce client, qui continuait de croire sa connexion valide. Le serveur informe désormais correctement le client dans ce cas, qui se reconnecte alors en une seconde environ ; le tableau de bord surveille en complément sa propre réception de données et force sa reconnexion s'il ne reçoit plus rien pendant quelques secondes.

## 2. Cohérence de la bibliothèque en temps réel

Un import, une modification de titre ou une suppression de vidéo se répercute désormais instantanément sur tous les écrans ouverts (sélection tactile, vitrine cinéma, bibliothèque d'administration) au lieu d'attendre le prochain sondage périodique.

## 3. Thème Charbon Sombre

Nouveau thème sombre, pendant du thème clair minéral « Charbon » existant, avec un accent gris acier plutôt qu'une teinte vive. Palette validée par calcul de contraste WCAG réel : niveau AAA sur le texte principal, le texte atténué et l'accent, niveau AA sur le texte discret (choix délibéré préservant la hiérarchie visuelle), et seuil « composant d'interface » respecté sur l'anneau de focus.

## 4. Installateur headless (Debian)

- **Paquets audio installés systématiquement** : `alsa-utils`, `pipewire`, `pipewire-pulse`, `wireplumber` et `pulseaudio-utils` étaient absents de la liste de paquets installée sur un Debian minimal, alors que le script configure déjà WirePlumber et appelle `amixer`/`pactl` — ces commandes échouaient silencieusement sans eux.
- **Détection de carte son généralisée** : un chemin système propre au Dell Wyse 5070 est remplacé par une détection dynamique de toutes les cartes présentes (HDA et USB).
- **Nouvelle étape de vérification** (`capabilities`, également disponible via `--check`) : confirme après coup que l'audio et le décodage vidéo matériel fonctionnent réellement, plutôt que de supposer que la configuration a suffi.
- **Nouvelle étape d'optimisation système** (`tuning`) : gouverneur CPU réglé en mode performance, journal système plafonné à 200 Mo.

## 5. Cache HTTP des fichiers statiques — toutes plateformes

Découvert en déployant cette version en conditions réelles : le mécanisme de revalidation de cache du frontend statique (introduit dans une version antérieure) ne fonctionnait pas correctement. L'identifiant de fraîcheur utilisé n'était pas réellement basé sur le contenu des fichiers, et un repli secondaire basé sur une date de fichier neutralisée par le processus de build reproductible pouvait faire considérer une page comme à jour alors qu'elle ne l'était pas. Un navigateur ou une vue Web intégrée pouvait ainsi continuer d'afficher une interface périmée après une mise à jour, sur n'importe quelle plateforme. Corrigé à la source, dans le composant partagé par toutes les plateformes.

## 6. Accélération matérielle Windows

Le réencodage vidéo sur Windows n'utilisait jusqu'ici jamais le GPU, contrairement à Android, macOS et Linux — trouvé lors d'un audit multi-plateforme. Le décodeur QuickSync Intel (présent sur la quasi-totalité des PC de bureau récents) est désormais tenté en premier, avec le même repli automatique vers l'encodage logiciel déjà en place sur les autres profils si le pilote n'est pas disponible.

## 7. Autres correctifs

- Section « Désinstaller » des réglages : la version Android affichait par erreur les instructions du profil Linux de bureau (`sudo apt remove`) au lieu des instructions Android.
- Section « Documentation » des réglages : clarification que les liens affichés (via l'adresse IP du réseau local) ouvrent la sortie réseau, distincte de la sortie câblée qui n'est accessible qu'en local sur la machine elle-même.
- Icône de zone de notification (Windows/macOS/Linux de bureau) : les liens « Administration » et « Kiosque » restaient figés sur le port par défaut si celui-ci avait été personnalisé dans la configuration.
- Documentation technique : plusieurs décomptes obsolètes corrigés (nombre de routes de l'interface, nombre d'étapes de l'installateur headless).
